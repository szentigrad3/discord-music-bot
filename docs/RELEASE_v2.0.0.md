# Discord Music Bot / BENDER v2.0.0 — stable release notes

Release date: 2026-11-02. Upgrade from v1.2.1.

## What's new

- Updated Discord now-playing controller with track metadata and interactive
  playback controls (pause/resume, back, skip, stop, loop, shuffle, volume).
- More reliable queue transitions, automatic advancement and skip behaviour.
  Per-guild pending queue limit of 500 tracks.
- Saved per-user, per-guild playlists in SQLite (save/list/show/load/add/remove/
  rename/delete); saved URLs persist across bot restarts.
- Lavalink 4 server reconnect/recovery: after server restart the bot waits for
  the new session, restores its voice handshake and attempts to resume the
  active track without destroying the queue.
- Graceful Docker SIGTERM/SIGINT handling: leave Discord voice before shutting
  down the Discord gateway, with an extended Compose stop grace period.
- Cross-channel protection: /play, /search and /playlist load never force-move
  an existing player into another member's voice channel.
- Safer initial Lavalink connection retries and source loading.
- Private v1.2.1 upgrade/migration script, Docker Lavalink ACL preparation and
  read-only Lavalink connection smoke test.
- Docker, Python 3.13/3.14 and security/queue regression coverage.

## Verification before merge

- Offline: Python 3.13 and Python 3.14 regression suites, Python compile
  checks and Docker Compose validation in GitHub Actions.
- Live (user-confirmed): multi-track queue, automatic advancement, skip,
  Lavalink 4.2.2 restart and playback recovery, saved-playlist persistence
  across bot restart, playback buttons, voice-channel permissions and the
  bot leaving Discord voice after a Docker stop.
- The cross-channel auto-move prohibition received additional regression
  coverage before the stable merge.
- Optional Spotify support depends on credentials and loaded Lavalink plugins.
  The Discord OAuth dashboard is disabled in the tested deployment and was
  not live-verified. Treat it as an optional feature, not a release-tested gate.
- A transient initial reconnection error may appear while Lavalink restarts;
  the bot retries and eventual restoration has been verified live.

## Safe upgrade from an existing checkout

The user previously migrated from the old private v1.2.1 ZIP into the
development checkout. **Do not repeat the importer** and do not overwrite
`settings.json`, `.env`, private Lavalink YAML, or `data/bot.db`.

```bash
cd ~/discord-music-bot-next
git status --short
git fetch origin
git switch main
git pull --ff-only origin main
bash scripts/test-all.sh
docker compose up -d --build --no-deps bot
docker compose ps
docker compose exec -T bot python scripts/lavalink_smoke.py
```

If the local `main` branch has uncommitted modifications, back them up
rather than overwriting them. This checkout should contain the ignored
private config and database already imported; check they exist before
switching branches. Do not run `docker compose down -v`.

## Release publication

The GitHub release workflow in `.github/workflows/release.yml` runs on
version tags matching `v*`, re-tests that exact source and then publishes
a GitHub Release with autogenerated notes. Only tag the merged, verified
`main` commit. The merge alone does not publish the GitHub Release.

## Security and limitations

- Never commit Discord tokens, Spotify credentials, `settings.json`,
  private Lavalink configurations or live SQLite databases.
- The dashboard is optional. Enable its session/OAuth configuration and
  test it separately behind HTTPS before offering it publicly.
- Lavalink/audio source availability depends on third-party services and
  plugins; live playback tests cannot guarantee future provider availability.
- A full bot container restart intentionally disconnects voice and does not
  persist an active playback session; only the *saved playlists* persist.
- For prior ZIP users or a separate installation, follow
  [the v1.2.1 migration guide](UPGRADE_FROM_1_2_1.md) instead of applying
  the checkout upgrade commands blindly.
